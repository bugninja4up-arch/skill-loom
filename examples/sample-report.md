# Synthetic review report

This is a fictional example for learning Skill Loom, not a customer incident.

During a documentation review, the team found that several suggested actions did not identify the observation supporting them. Recommendations mixed confirmed facts with guesses, and some items included identifying details copied from the input.

The team agreed on three lessons:

- For each proposed action, point to a specific observation in the supplied report.
- Label uncertainty explicitly. If evidence is missing, ask a focused question rather than inventing a cause, a filename, a quantity, or a result.
- Remove identifying details and secrets when converting a one-time report into reusable guidance.

Keep the existing review structure. Add only concise instructions that are genuinely new; do not paste this report into the skill or invent numerical results.
